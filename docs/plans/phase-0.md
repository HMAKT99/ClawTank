# Phase 0 — Research and foundations

## Goals
- Verify IronRDP server, EGFX and channel maturity (`docs/research/ironrdp.md`).
- Spike `CGVirtualDisplay` + ScreenCaptureKit on current macOS (`docs/research/virtual-display.md`).
- Record foundational ADRs (`docs/decisions.md`): architecture, FFI, auth, virtual-display risk, min macOS, project generator.
- Scaffold the repo: Rust workspace (`core/`), SwiftUI menu-bar app (`app/`), Makefile, CI, licenses and community docs.

## Decisions already made (by the maintainer)
- Name: **ClawTank**.
- Auth: dedicated app password in Keychain, used for NLA/CredSSP.
- FFI: hand-written C ABI, header generated by cbindgen.
- Git: local only for now; CI workflow written but not yet run on GitHub.

## Files touched
`core/**`, `app/**`, `spikes/virtual-display/**`, `scripts/**`, `.github/workflows/ci.yml`, `Makefile`, top-level docs.

## Risks
- `CGVirtualDisplay` is private API; may change between macOS releases. Mitigation: isolate behind a protocol, feature-detect, fall back to physical display.
- IronRDP server-side channels may be incomplete (especially RDPDR). Mitigation: documented in research; decide per phase.
- CI cannot be verified until the repo is pushed to GitHub.

## Verification
- `make build` produces `ClawTank.app` linked against `libclawtank_core.a`; the app's menu displays the Rust core version.
- `make test` and `make lint` pass locally.
- The spike produces a PNG captured from a 2560×1600 HiDPI virtual display (requires a Screen Recording grant).
