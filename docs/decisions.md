# Architecture Decision Records

Format: context → decision → consequences. Newest last. Status is *Accepted* unless noted.

## ADR-001 — Rust protocol core + Swift native host
**Context.** We need a full RDP server (TLS, NLA, EGFX/H.264, virtual channels) plus deep macOS integration (ScreenCaptureKit, VideoToolbox, CGEvent, private CGVirtualDisplay). IronRDP (Apache-2.0/MIT) has a maintained, feature-rich server crate; macOS APIs are best used from Swift.
**Decision.** Protocol in Rust on `ironrdp-server` (pinned, `egfx` feature). Everything Mac-specific in Swift. Rust is built as a static library linked into the app.
**Consequences.** Two toolchains (cargo + Xcode). The FFI boundary must stay narrow. Our protocol behavior tracks IronRDP releases, so we contribute fixes upstream (e.g. IronRDP #2148).

## ADR-002 — FFI: hand-written C ABI, header generated by cbindgen
**Context.** Options: UniFFI, swift-bridge, hand-written C ABI. The hot path will pass IOSurface-backed frames and encoded H.264 buffers; we want zero-copy and an auditable, fuzzable surface.
**Decision.** `extern "C"` functions with a `ct_` prefix and `#[repr(C)]` types live only in `core/clawtank-core/src/ffi.rs`. `build.rs` runs cbindgen to emit `core/include/clawtank_core.h`, and Swift imports it as module `ClawTankCore` via a module map. Strings returned to Swift are `'static`. Release builds use `panic = "abort"`, so nothing unwinds across the boundary.
**Consequences.** More boilerplate than codegen tools, but no hidden copies or runtime. Every new FFI function needs a Swift wrapper in `CoreBridge` and a fuzz/unit test.

## ADR-003 — Authentication: dedicated app password for NLA
**Context.** NLA (CredSSP/NTLM) requires the server to know the plaintext password or its NT hash. A macOS login password cannot be checked that way without storing a copy. Stock `mstsc` and Windows App must work with default settings (NLA on).
**Decision.** On first run the user sets a ClawTank password. It's stored in the Keychain and passed to `RdpServer::set_credentials` with the macOS short username. Lockout, rate limiting and audit logging go through IronRDP's `CredentialValidator` hook.
**Consequences.** Users type a separate password in their client. A macOS password change doesn't break RDP. NTLM is weak against offline cracking of captured exchanges, which is one more reason to stay LAN-only by default and to enforce a minimum password strength. Kerberos is out of scope.

## ADR-004 — Virtual displays via private `CGVirtualDisplay`, isolated and optional
**Context.** Headless Macs and resolution matching need a virtual display. No public API exists. `CGVirtualDisplay` (CoreGraphics, private) works on macOS 15.6 (see docs/research/virtual-display.md).
**Decision.** Access it only through a `VirtualDisplayProvider` protocol. Feature-detect with `NSClassFromString`, guard every call, and fall back to capturing the physical display. Sweep stale displays at launch. Interface declarations live in a single ObjC header.
**Consequences.** Not App-Store-eligible (already a non-goal). It may break in a future macOS, which the fallback limits to a degraded experience rather than an outage. We test on each macOS beta.

## ADR-005 — Minimum macOS 14 Sonoma
**Context.** ScreenCaptureKit's `SCScreenshotManager`, `MenuBarExtra` and `SMAppService` are available on 14. Nothing so far requires 15.
**Decision.** Deployment target 14.0. Raise it only through a new ADR.
**Consequences.** We must test on 14 before releases (CI runs macOS 15 runners only).

## ADR-006 — Xcode project generated by XcodeGen
**Context.** Hand-edited `.pbxproj` files cause merge conflicts and are hard to review.
**Decision.** `app/project.yml` is the source of truth. `make project` generates `ClawTank.xcodeproj`, which is git-ignored.
**Consequences.** Contributors need `brew install xcodegen`. Opening the project in Xcode requires `make project` first.

## ADR-007 — Build for the host architecture; universal later
**Context.** We optimize for Apple silicon. A universal binary doubles Rust build time and needs the `x86_64-apple-darwin` target.
**Decision.** `make build` builds for `$(uname -m)`. Universal (lipo) packaging will be added to `make release` in Phase 10 if Intel support stays cheap.
**Consequences.** Dev builds are fast. Release tooling has to handle lipo.

## ADR-008 — Accept RUSTSEC-2023-0071 (`rsa` Marvin attack) for now
**Context.** `cargo audit` flags `rsa 0.10.0-rc.18`, pulled in by IronRDP's `picky`/`sspi`. No fixed version exists. The attack needs an RSA PKCS#1 v1.5 *decryption* oracle using the server's private key.
**Decision.** Ignore it in `core/.cargo/audit.toml`, after verifying our path: TLS private-key operations go through rustls with aws-lc-rs; NLA uses NTLM (HMAC/RC4, no RSA); Kerberos (whose sspi decrypts are symmetric anyway) is not enabled. We also raised the workspace MSRV to Rust 1.88 to take `time ≥ 0.3.47` (RUSTSEC-2026-0009).
**Consequences.** We re-check this whenever IronRDP is bumped and remove the ignore once `rsa` ships a constant-time release. If we ever enable Kerberos or RSA key transport, this ADR must be revisited.
